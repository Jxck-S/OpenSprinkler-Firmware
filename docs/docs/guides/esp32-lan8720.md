# ESP32 + LAN8720 Wired Ethernet (Community Build)

This guide covers building OpenSprinkler firmware for a **classic ESP32 with an RMII Ethernet PHY** such as the LAN8720, for example the **WT32-ETH01**. It's a do-it-yourself controller that uses wired Ethernet without a Raspberry Pi.

!!! warning "Community build"
    This is not official OpenSprinkler hardware. Builds use their own firmware update target (`esp32-lan8720`), so they never install official ESP32-C6 releases. Update them by uploading a `.bin32eth` file from the web UI. Bench-test with valves disconnected before connecting real zones.

## What you need

- A classic ESP32 with a LAN8720 (or another RMII PHY supported by Arduino-ESP32: IP101, RTL8201, DP83848, KSZ8081). ESP32-S2, S3, C3 and C6 have no RMII Ethernet controller.
- A relay board, plus either an I2C I/O expander or spare GPIOs (see [Wiring styles](#wiring-styles)).
- A 5V supply (see [Power](#power)).

## Presets

The RMII data pins are fixed in the ESP32 and the same on every board: GPIO 19, 21, 22, 25, 26 and 27. Only the settings below differ, and each preset is one PlatformIO environment.

| Environment | PHY addr | MDC / MDIO | PHY power | 50 MHz clock | I2C SDA / SCL | GPIO station pins |
|---|---|---|---|---|---|---|
| `esp32_lan8720_wt32_eth01` | 1 | 23 / 18 | 16 | GPIO0 in | 33 / 32 | 4, 5, 14, 15, 17 |
| `esp32_lan8720_generic` | 1 | 23 / 18 | none | GPIO0 in | 33 / 32 | 4, 5, 13, 14, 15 |

### Adding a board

Add an environment to `platformio.ini` that extends `esp32_rmii` and sets only the flags that differ. All options and their defaults are in `boards/rmii_config.h`.

```ini
; example values: take yours from the board's schematic
[env:esp32_lan8720_myboard]
extends = esp32_rmii
build_flags =
	${esp32_rmii.build_flags}
	-DOS_ETH_PHY_ADDR=0
	-DOS_ETH_PHY_POWER=12
	-DOS_ETH_CLK_MODE=ETH_CLOCK_GPIO17_OUT
	-DOS_I2C_SDA=13
	-DOS_I2C_SCL=16
	-DOS_GPIO_FREE_PINS=4,32,33
```

| Flag | Meaning |
|---|---|
| `OS_ETH_PHY_TYPE` | `ETH_PHY_LAN8720` (default), `ETH_PHY_IP101`, `ETH_PHY_RTL8201`, ... |
| `OS_ETH_PHY_ADDR` | PHY address, usually 0 or 1 |
| `OS_ETH_PHY_MDC`, `OS_ETH_PHY_MDIO` | management pins (usually 23 / 18) |
| `OS_ETH_PHY_POWER` | GPIO that enables the PHY or its oscillator, `-1` if none |
| `OS_ETH_CLK_MODE` | `ETH_CLOCK_GPIO0_IN`, `ETH_CLOCK_GPIO0_OUT`, `ETH_CLOCK_GPIO16_OUT`, `ETH_CLOCK_GPIO17_OUT` |
| `OS_I2C_SDA`, `OS_I2C_SCL` | I2C bus for the expander and OLED |
| `OS_GPIO_FREE_PINS` | comma list of pins offered for GPIO stations (no braces) |

The build fails with a clear error if an I2C or GPIO station pin collides with RMII, the internal flash (6–11), UART0 (1, 3), GPIO12 (a boot strapping pin), or an input-only pin (34–39).

## Wiring styles

One firmware image supports all three styles, detected or configured at runtime.

### 1. PCA9555 expander + active-high relays (recommended)

- PCA9555 at **I2C address 0x20** (A0–A2 to GND), powered from **3.3V**.
- **P0.0–P0.7** are zones 1–8, and a pin goes high to turn a zone on. Use a relay board set to active-high (H/L jumper on H), or a ULN2803 driver.
- **P1.0–P1.2** are buttons B1–B3 (to GND, active-low). They're optional.
- More zones: add expansion boards at 0x24 and up, as on standard OpenSprinkler.

### 2. PCF8574 expander + common active-low relay board

- PCF8574 at **0x20**, powered from **3.3V**.
- **P0–P7** are zones 1–8. The firmware inverts the outputs, so the typical "IN low = relay on" board works directly.
- PCF8574 pins power up high, so relays stay off during boot.
- No buttons: the PCF8574 has only 8 pins.

### 3. No expander: GPIO stations

Wire relay inputs straight to the preset's GPIO station pins. In the app, set each zone's station type to **GPIO**, pick the pin, and choose **active high or low** to match your relay board. Configured GPIO stations are driven to "off" at boot.

!!! note "Boot glitches"
    GPIO 5, 14 and 15 output a few milliseconds of signal while the ESP32 boots. A relay may click, but a 24VAC valve won't open in that time. Pins 4, 13 and 17 are clean. Never put a pull-up on GPIO2, and never use GPIO12.

### Relay board power

Opto-isolated relay boards with a **JD-VCC** jumper: remove the jumper, feed **VCC with 3.3V** (logic side) and **JD-VCC with 5V** (relay coils).

## Power

The relays and the ESP32 need **5V**. The solenoids keep using your **24VAC** transformer through the relay contacts.

- 5V/2A wall supply, or
- an 802.3af **PoE splitter** with 5V output (one cable for data and power), or
- 24VAC → bridge rectifier → capacitor (about 34V DC) → a buck converter rated for **at least 40V input** (e.g. LM2596**HV**). Common MP1584 and MP2307 modules can't take that voltage.

## Building and flashing

```bash
npm ci
pio run -e esp32_lan8720_wt32_eth01
```

The first time, flash over USB-serial. The WT32-ETH01 has no USB port: connect a 3.3V USB-UART adapter to TX0/RX0, hold **IO0 to GND** while powering up, then:

```bash
pio run -e esp32_lan8720_wt32_eth01 -t upload --upload-port /dev/tty.usbserial-XXXX
```

After that, update from the web UI by uploading `.pio/build/<env>/firmware.bin32eth`.

## Limitations

- **No current sensing:** undercurrent and overcurrent alerts are disabled.
- **No direct sensor or RF pins:** rain or flow sensors and RF stations aren't available on this profile.
- **4MB flash:** two 1.75 MB OTA slots and 384 KB of storage, so on-device log history is shorter than on 8MB boards.
- **No Zigbee or Thread:** the classic ESP32 has no 802.15.4 radio.
- The app shows hardware version 4.0 because the firmware runs the same ESP32 feature set.
